## 自动暂停行为

当前只有一条内置规则：实际发出 `gpt-6-astra`，原始上游响应返回 `gpt-5.6-luna`。

- HTTP 转发返回前同步检查，WebSocket 每轮结束、异步计费回调前检查。
- 先设置进程内调度阻断，再通过现有 `SetSchedulable(false)` 持久化暂停；该方法同步调度账号快照并写入调度 outbox。
- 暂停整个账号，保留 `status=active`；不设置自动恢复时间，不改变正常 token 刷新。可在账号管理中使用现有开启调度操作恢复。
- 当前响应正常交付，正常记录用量；不重放已输出的请求。已发出的其他并发请求不会被强制取消。
- 当前 WebSocket 会话命中后，拒绝后续轮次，让客户端重连选择其他账号；调用方原有生命周期回调保持执行。
- 客户端断开后，暂停写入使用独立的 5 秒上下文，不随请求取消。
- 暂停原因写入结构化日志：`openai_model_route_account_paused`，附账号 ID、请求 ID、发送模型、响应模型及规则名。数据库写入失败会记录 `openai_model_route_pause_failed`，此时只有现有的 2 分钟进程内阻断保证，不声称持久暂停成功。

不会触发：正常 Luna 请求、已明确映射为 Luna 的出站请求、其他模型差异、缺少实际返回模型、失败的 WS 轮次。当前不将 `gpt-6-astra-pro` 或未知后缀自动扩展为此规则。

上游终态模型优先于首帧声明。例如 `response.created` 声明 Astra，但 `response.completed` 声明 Luna，仍然触发暂停。
