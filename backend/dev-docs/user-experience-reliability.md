# 用户体验与连接诊断

## 并发与连接

WebSocket 后续轮次的并发准入最多短等 3 秒。先尝试立即获取用户和上游账号槽位；未同时获得时释放已获得的槽位，再进入有上限的共享等待队列。等待支持客户端取消，成功或失败都会清理排队计数。只有准入成功才记录 Key 当前并发，准入后重新核对当前定价窗口与账号资格。

原生连接池、HTTP 桥接和透传入口持续读取客户端控制帧。原生连接池在尚未输出时取消断线请求；已输出时保留最多 30 秒的上游用量收尾，收尾后将相关上游连接标记为不可复用。已收到输出的轮次不能自动重放。

本次没有调整轮间空闲超时。配置示例 `gateway.openai_ws.ingress_inter_turn_idle_timeout_seconds` 为 300 秒；本轮没有新鲜生产配置或断线分布证据，不能据此推断生产取值或盲目延长。后续调整应先统计关闭原因、实际路由模式、工具执行时间与首输出耗时。

## 错误详情

用户错误详情增加处理建议、重新加载与故障信息复制。建议使用粗分类及明确的机器错误码，避免根据任意上游报错文本断言用户 Key 或余额异常。

复制内容采用白名单：错误编号、时间、Key 名称、模型、入口路径、状态、分类、平台与客户端。排除 IP、请求内容、原始报错、账号内部信息，并去除查询参数和常见凭据格式。接口原有用户归属校验保持不变。

详情加载在记录切换、关闭和组件销毁时取消旧请求，并校验请求版本，防止慢响应覆盖当前记录。用户分类过滤使用与展示相同的 phase/type 优先级；“其他”有独立的精确匹配条件，不再等同于无过滤。

## 接入诊断

在“使用 Key”的 Codex 配置向导中展开“配置检查与连接诊断”：

1. 检查基础地址格式，拒绝带凭据、查询参数或具体接口路径的地址。
2. 手动检查模型列表与鉴权，并验证所选模型是否在列表中。
3. 用户勾选计费提示并点击发送后，才执行一次简短的 Responses 流式请求。成功必须收到终止事件，不能仅凭 HTTP 200、心跳或 `[DONE]` 判断。
4. 浏览器不能为 WebSocket 设置本站所需的认证头，因此提供 `frontend/public/connection-diagnostics.mjs`，供用户在客户端电脑运行。

浏览器模型检查限制 15 秒；流式测试限制 45 秒，并限制响应体大小。测试关闭、配置改变和取消都会终止旧请求。HTTP 重定向不携带 Key 自动跟随。

本地脚本需要 Node.js 20+，默认仅检查模型列表和 WebSocket 握手，不发送 `response.create`。用户自行添加 `--stream` 才授权一次可能计费的 HTTP 生成。脚本不会读取客户端软件内部的代理设置，握手成功不能证明整轮 WebSocket 模型请求成功。

界面运行命令包含用户自己的 Key；可复制的诊断报告和脚本标准输出不包含 Key。脚本通过环境变量接收 Key，公开下载文件中没有嵌入凭据。

## 验证范围

相关后端测试覆盖双槽获取/释放、等待取消、队列满、原生连接控制帧、断线取消、用量收尾及错误过滤的用户归属保护。前端测试覆盖旧响应覆盖、诊断显式触发、计费授权、SSE 终止判定与脱敏报告。本地脚本测试使用临时 HTTP/WebSocket 服务，无生产模型调用。

诊断脚本的本地测试可在 `frontend` 目录执行：

```sh
node --test src/utils/__tests__/connection-diagnostics.node.test.mjs
```
